Before you press anything

Two things judge the weight, and only one closes the tray.

The scale prints its own UNDER / OVER / OK flags from its Target Table. The MES ignores those flags and judges the net weight itself against the pack-out above. Both are set to 50 ± 2 lb, so on every cycle compare the flags in the Message tag with the MES verdict in the scale log. A mismatch is a finding, most likely at the exact limits.

Keep the device Packet Based.

Template 3 has no line break after its last line. The “MPP Scale” device is Packet Based, which hands over each record as it arrives. A Character Based device waiting for \r or \n would hold the last line until the next print. Setup step 5 confirms one print arrives as one value.

Don't run a second listener on port 1702.

The gateway holds the scale's EPrint connection. Malaki's PowerShell reader opens a second client on the same port, which can take the prints away from Ignition. Disable the device in the gateway before you use it.

Every good cycle prints a shipping label.

Each good cycle completes a box (1 tray per box), which claims an AIM shipper ID from the Dev pool (294 free; AIM posting is off) and prints a shipping label on P - 018. That printer goes through the USB bridge on the laptop at 10.20.11.157:9100, set up the same way as P-034.

Setup

  1. Scale front panel (Malaki's setup, serial B913444851). Check:
    • Input 0.1.1 is assigned Enter.
    • ID1 is Automatic, Threshold 0.5, Reset 0.25, with the five steps TARE prompt, Tare - Auto, PRINT prompt, Print, Clear Tare.
    • The Connections row is EPrint, Demand Output, Trigger Scale, Template 3. No other Demand Output row has Trigger Scale.
    • Secondary port is 1702, DHCP is off, and the IP is 10.20.11.150.
    • TaskExpert Start is empty and units are lb.
    • The active target is loaded: press TARGET and expect Active Values 50, +2, −2. If they are blank, use softkey 6 (Target Table) and pick the 50 lb part record.
  2. Import the UDT. Designer, Tag Browser, MPP provider, UDT Definitions: Import ignition/tags/udt/ScaleStationEPrint.json.
  3. Create the instance. Under [MPP]PlcDevices, new UDT instance of ScaleStationEPrint named exactly MPP_Scale. Parameters: Device = MPP Scale (with the space), BasePath = 1702/, OpcServer left at Ignition OPC UA Server. Message and LastReceiveTime should read Good.
  4. Console check (Designer Script Console): 
    print BlueRidge.Parts.ContainerConfig.judgeWeight(110, "ByWeight", 50.0)
print BlueRidge.Workorder.ScaleEPrintWatcher.parse("      56.0 lb \r\n      49.8 lb T \r\n       6.2 lb N \r\nUNDER: 1 OVER: 0 OK: 0")
    Expect Verdict = Ok with limits 48 and 52, then a dict with 'net': 6.2. Do not call handleMessage from the console; it runs the real close.
  5. Open the terminal. On the office laptop, open a new Perspective session on the MPP project. Its IP now resolves to MA2-6MAOP-AOUT (Assembly Out, 6ma oil pan). A session opened earlier still holds the 64A Oil Pan terminal until it is reloaded. Refusal toasts only show in a session bound to terminal 106.
  6. One light cycle. Place an empty container (over 0.5 lb), press (tare), add about 5 lb, press (print). Watch Message: it should change once and hold all four lines in one value. This first cycle is judged for real: expect an UNDER toast, no close, and UNDER: 1 in the flags. That proves the whole path without spending stock.

Tests

Every test is one scale cycle: place the container, press (tare), add weight, let it settle, press (print), remove everything. Only the print press reaches the MES. After each cycle, run the scale log query below (each print leaves one row) and note the scale's flags from Message.

T1

Good tray closes

Cycle
Net about 50 lb.
Expect
Within a second or two of the print press: log row ByWeight tray close with verdict=Ok; a new FG LOT of 60; the box complete with an AIM shipper ID; each BOM child down by 60 (540 left); the Assembly Out screen refreshes; a shipping label prints on P-018.
Scale
Flags read OK: 1. Malaki has not yet seen OK print, so this result settles his open item.
T2

Same weight twice

Cycle
Repeat T1 with the same weight.
Expect
A second close and a second box. Two identical records in a row is the case the receive-stamp trigger exists for. If nothing happens, the trigger is keyed on the message text, not the stamp.
T3

Light tray refused

Cycle
Net about 40 lb.
Expect
UNDER weight toast (a warning that clears on the next good tray), log row Tray not closed with verdict=Under. No LOT, stock unchanged. Scale flags UNDER: 1.
T4

Heavy tray refused

Cycle
Net about 60 lb.
Expect
OVER weight toast, verdict=Over, no close. Scale flags OVER: 1.
T5

The limits

Cycle
Net exactly 48.0, then exactly 52.0, then 47.9 and 52.1 (the scale reads in 0.1 lb steps).
Expect
The MES closes at 48.0 and 52.0 and refuses 47.9 and 52.1. Write down what the scale's flags say at 48.0 and 52.0. If the scale calls them Under or Over, the two judges disagree at the limits.
T6

Cycles that should not close

Do
Run these one at a time: tare only, then lift the container off; press while the platform is moving; press twice quickly at the print step; empty platform, press.
Expect
No close unless a full record was printed. A tare press sends nothing, so it leaves no log row. Note anything the scale does that the operator would not expect; Malaki listed these as untested.
T7

Wrong units

Cycle
Optional. Switch the terminal to kg, run a cycle, switch back.
Expect
Scale is in the wrong units error toast that stays on screen. No conversion, no close.
T8

Disarm works

Do
Run the teardown below (or deprecate the mapping in Config Tool, PLC Devices). Run a good cycle.
Expect
Nothing: no log row, no close.

Checking results

Scale log (one row per press)

SELECT TOP 10 Id,
       CAST(LoggedAt AT TIME ZONE 'UTC' AT TIME ZONE 'Eastern Standard Time' AS DATETIME2(0)) AS LoggedET,
       Description, RequestPayload, ErrorDescription
FROM Audit.InterfaceLog
WHERE SystemName = N'PLC:MPP_Scale'
ORDER BY Id DESC;

Trays, boxes and labels

SELECT TOP 10 c.Id AS ContainerId, cs.Code AS Status, t.ClosureMethod, t.PartsClosedCount,
       fg.LotName AS FgLot,
       CAST(t.ClosedAt AT TIME ZONE 'UTC' AT TIME ZONE 'Eastern Standard Time' AS DATETIME2(0)) AS ClosedET,
       sl.AimShipperId, sl.LastPrintError
FROM Lots.ContainerTray t
JOIN Lots.Container c ON c.Id = t.ContainerId
JOIN Lots.ContainerStatusCode cs ON cs.Id = c.ContainerStatusCodeId
LEFT JOIN Lots.Lot fg ON fg.Id = t.FinishedGoodLotId
LEFT JOIN Lots.ShippingLabel sl ON sl.ContainerId = c.Id AND sl.IsVoid = 0
WHERE c.ItemId = 110
ORDER BY t.Id DESC;

BOM stock left at the line

SELECT i.PartNumber, i.Description, SUM(l.InventoryAvailable) AS Available
FROM Lots.Lot l
JOIN Parts.Item i ON i.Id = l.ItemId
JOIN Lots.LotStatusCode s ON s.Id = l.LotStatusId
WHERE l.CurrentLocationId = 104 AND s.Code = N'Good'
  AND l.ItemId IN (13, 106, 107, 111, 112, 113, 114)
GROUP BY i.PartNumber, i.Description
ORDER BY i.PartNumber;

When a result is wrong

You seeIt means
Nothing, and no log rowThe tag-change did not fire. Check LastReceiveTime moved, the instance is named MPP_Scale, and the gateway log for “no TerminalPlcDevice mapping”.
“Scale weighment not read”The direct OPC read of Message failed. This is one of the two assumptions never yet seen working. Report it; the fix is in _readMessage.
Logged net= is the previous press's weightSame area, worse outcome. Disarm straight away.
“printout has no net weight line” or “2 net weight lines”The record was split across packets, or two records were merged. Check whether one print shows as one value in Message.
“receive stamp ... old, not a live press” in the gateway logThe gateway and scale clocks disagree by more than 30 s, or the stamp is stale after a reconnect. Press again; if it repeats, compare clocks.
Closes every cycle but always reads highThe tare press did not take (motion, or below zero), so the net includes the container.
Record arrives only at the next printThe device is waiting for a line break. Keep it Packet Based (see the note at the top).
“No ByWeight pack-out” or “not eligible”The ByWeight row was deprecated or edited without PartsPerTray. Check Item Master, Container Config.

Teardown

Disarm by restoring the tag-change resource to its committed state (empty path list) and rescanning:

git checkout -- ignition/projects/MPP/ignition/tag-change/ScaleEPrintMessage/resource.json
.\scan.ps1

The mapping, ByWeight pack-out, stock and the UDT instance can stay on Dev for the next session. To take the scale off the terminal entirely, deprecate the MPP_Scale row in Config Tool, PLC Devices.

# Pass-Through Parts Screen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the three-tab `ThirdPartyInspection` station into a two-tab pass-through parts screen — **Inventory** (receive a vendor part, print its LTT, see what is on hand) and **Assembly** (consume it into a finished good) — without navigating away from either tab.

**Architecture:** `ThirdPartyInspection/view.json` becomes a two-tab shell embedding `ReceivingDock` (with a new `embedded: true` param) and `AssemblyNonSerialized` (unchanged). `ReceivingDock` gains an embed mode that suppresses its two `navigate()` calls, broadcasts the page-scoped `inventoryChanged` message the Assembly tab already listens for, hides its Close button, and shows an on-hand panel. One read proc gains a status column so the on-hand card stops claiming every LOT is `Good`.

**Tech Stack:** SQL Server 2022 (repeatable stored procs, `sqlcmd`), Ignition 8.3 Perspective (file-based `view.json`), Jython 2.7 project scripts.

**Spec:** `docs/superpowers/specs/2026-08-06-pass-through-parts-screen-design.md`

## Global Constraints

- **The route and view path do NOT change.** `/shop-floor/third-party-inspection` and `BlueRidge/Views/ShopFloor/ThirdPartyInspection` stay exactly as they are — they are seeded as `DefaultScreen` in `sql/seeds/011_seed_locations_mpp_plant.sql:923`, `sql/scripts/reconcile_location_dev.sql:1100`, and generated by `sql/seeds/gen_locations_mpp.js:79`. Touch none of those three files.
- **Designer must be closed** for every Ignition file edit in this plan. Designer silently reverted a view twice on 2026-08-05. After editing, run `.\scan.ps1` from the repo root.
- **Both `view.json` files round-trip byte-identically** through `json.loads` → `json.dumps(d, indent=2, ensure_ascii=False)` → CRLF → trailing CRLF (verified 2026-08-06). Every view edit in this plan therefore uses a **Python object-model mutation**, not the Edit tool and not string splicing. Task 2 Step 1 re-proves this before any mutation.
- **Never write view files with PowerShell `Set-Content` / `Out-File`** — they emit a UTF-8 BOM, which silently breaks Ignition tooling. Use Python `io.open(..., 'w', encoding='utf-8', newline='')`.
- **SQL tests run against `MPP_MES_Test`, never `MPP_MES_Dev`.** `Run-Tests.ps1` DROPs its target database and defaults to `MPP_MES_Test`; do not pass `-DatabaseName`.
- **A filtered test run is not sufficient after a read-proc shape change.** A widened result set breaks a fixed-shape `INSERT-EXEC` capture as `Msg 213` / runner exit-1, **not** as a `FAIL:` line, and filtered runs still pass. Grep the full-suite output for **both** `FAIL:` and `ERROR running`.
- **Stored procs are `CREATE OR ALTER`.** Deploy a changed repeatable to Dev with `sqlcmd` directly — never reset `MPP_MES_Dev` (hand-built data, no backups).
- **All SQL string literals stay ASCII-only.** `sqlcmd` reads `.sql` in the Windows codepage; an em-dash becomes `â€"` and surfaces as mojibake in Ignition toasts.

## Task 2: `ReceivingDock` gains an `embedded` mode

It also never sends the page-scoped `inventoryChanged` message that `AssemblyNonSerialized` already listens for, so the sibling tab's component projection goes stale after a receive.

Everything here is gated on a new `embedded` param defaulting to `false`, so standalone `/shop-floor/receiving` is bit-for-bit unchanged in behaviour.

**Files:**
- Modify: `ignition/projects/MPP/com.inductiveautomation.perspective/views/BlueRidge/Views/ShopFloor/ReceivingDock/view.json`

# --- 2. custom.refreshToken (drives the Task 3 on-hand re-read) ---------------
d.setdefault('custom', {})['refreshToken'] = 0


def find(node, name):
    if node.get('meta', {}).get('name') == name:
        return node
    for child in node.get('children', []) or []:
        hit = find(child, name)
        if hit:
            return hit
    return None
